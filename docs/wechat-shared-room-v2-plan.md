# 微信小程序分账 V2.1：本地快算与群组共享

## 产品结论

小程序首页明确提供两种使用方式，而不是把共享入口夹在本地表单上方：

1. **本地快速分账**：手动输入参与人和支出，数据只保存在当前设备，适合一次性计算。
2. **共享账单**：从空白房间开始，发送小程序卡片到现有微信群，成员以服务端确认的微信身份加入并共同记账。

两种模式共用币种、支出编辑、结算算法、分享文字和结算图，但不自动互相导入或同步。产品定位保持为安静、清楚、可靠的中文工具；不增加营销式 branding、荧光色、装饰性入口或无必要的二级设置页。

成员的完整昵称始终显示，因此头像位不再重复首字母。默认使用账单内稳定分配的动物或食物 Emoji，用户可以选择更换，但这不是创建或加入账单的必经步骤。系统不请求、上传或保存真实微信头像。

## 1. 首页信息架构

### 1.1 模式选择

应用栏下方放置一个紧凑、常驻的双选入口：

- `本地快速分账` — `只保存在本机`
- `共享账单` — `邀请朋友共同记账`

要求：

- 默认选中本地模式；从邀请卡片或共享历史进入时直接进入对应共享房间，不绕回首页选择。
- 两个入口在视觉上同级，选中态清楚但克制；使用中性色与现有深绿操作色，不用荧光绿、渐变或大面积品牌文案。
- 切换模式不得清空尚未提交的本地表单或共享创建表单。
- 未配置 CloudBase 时，共享入口明确显示暂不可用；本地模式仍完整可用，不能显示虚假的云端成功。
- 320、390、430px 视口下入口、表单和主要按钮不横向溢出，点击区域至少 44px。

### 1.2 本地快速分账

选中后显示现有三段工具流程：参与人、支出、结算。保留支出编辑、保存并新建、历史和分享；移除重复设置入口和不必要解释，优先让用户在一屏内看到下一步操作。

### 1.3 共享账单

选中后直接显示内联创建表单，不再弹出二级对话框：

- 账单名称
- 币种
- `你在账单里的昵称`（微信昵称输入组件，允许复用设备上最近一次确认值）
- 自动分配的 Emoji 预览和可选的“换一个”
- `创建共享账单`

创建不依赖本地参与人或支出。创建成功后进入空房间，主要操作是添加支出和发送邀请。

## 2. Emoji 成员标记

### 2.1 体验规则

- 使用固定白名单中的 50 个大众动物和食物 Emoji；不使用旗帜、肤色人物、宗教、政治或容易产生歧义的符号。
- 新参与人自动获得一个 Emoji。同一账单内有未占用 Emoji 时自动分配不得重复。
- 自动结果保存到该账单的数据中，因此刷新、重启、换设备、历史记录和结算分享图保持一致。
- 完整昵称始终显示；Emoji 只是快速识别标记，不能替代姓名，也不参与排序、结算或权限判断。
- 点击自己的 Emoji 可打开紧凑选择面板；提供 50 个选项、`随机一个` 和 `恢复自动分配`。创建/加入流程不强迫用户打开选择面板。
- 本地账单创建者可修改任意手动参与人的 Emoji；共享账单成员只能修改自己的 Emoji。
- 用户主动选择可以与其他成员重复；界面不阻止，但自动分配仍优先避重。

### 2.2 数据契约

- 本地 participant 增加经过白名单校验的 `avatarEmoji`。新建时立即写入；旧记录缺失该字段时按稳定 ID 自动补全，并在下一次正常保存时持久化。
- 共享 participant 与对应 member 保存同一个房间级 `avatarEmoji`；加入事务自动分配，资料更新事务同时更新两份记录。
- 邀请预览不返回成员昵称、Emoji、成员列表、支出或余额。
- 服务端只接受白名单内的单个 Emoji；拒绝 URL、文件 ID、HTML、组合字符串、未知字段和超长输入。
- 不建立跨房间 profile；相同微信用户在不同房间可以有不同昵称和 Emoji。
- 不增加头像上传、CloudBase 文件、公开 URL、临时下载链接或头像缓存。

### 2.3 分配规则

自动分配使用可复现的账单级算法：

1. 以 `roomId/ledgerId + participantId` 计算候选起点。
2. 从候选起点顺序查找当前账单中第一个未占用的白名单 Emoji。
3. 分配结果写入 participant；共享模式必须在服务端事务内完成。
4. 账单人数超过白名单数量时才允许自动重复；共享房间现有限额低于 50，应始终可以避重。
5. `恢复自动分配` 重新执行同一规则并保存；`随机一个` 从当前可用集合选择并保存。

## 3. 共享账单用户流程

### 3.1 房主

1. 在首页选择“共享账单”。
2. 输入账单名称、币种和账单内昵称；系统已展示默认 Emoji，可直接创建。
3. 服务端根据当前请求的 `OPENID` 原子创建 owner member、对应 participant 和空账单。
4. 房主把带高熵邀请 token 的小程序卡片发到现有微信群。

### 3.2 受邀成员

1. 打开卡片后只看到账单名称、币种、当前人数和隐私提示。
2. 服务端用当前请求的 `OPENID` 判断其是否已经加入。
3. 新用户只需确认账单内昵称；加入时由服务端自动分配 Emoji，进入房间后可随时更换。
4. 加入事务创建唯一 editor member 和 participant；不显示或接受“认领参与人”。
5. 已加入用户再次打开邀请直接进入房间；过期、撤销或耗尽的邀请不能授权新成员。

### 3.3 共同记账

- 每位有效成员可以新增、编辑和删除支出；新增付款人默认自己。
- 房间页面打开时立即刷新，在前台约每 2.5 秒轮询；离线只读。
- 房主可以生成/撤销邀请、移除成员、归档和删除；普通成员可以退出。
- 被移除或退出的成员在下一次请求时失去云端访问。设备上已同步缓存无法远程擦除，重新联网后清除。
- 本地账单不自动上传；第一版不提供本地账单导入共享房间。

## 4. 身份、权限与隐私边界

### 4.1 资产与参与者

- 资产：微信身份、房间昵称、Emoji、成员关系、邀请 token、支出、余额与结算结果。
- 参与者：房主、有效成员、受邀未加入用户、已退出/被移除成员、非成员和 CloudBase 管理端。
- 入口：创建、邀请预览、加入、读取房间、资料更新、支出变更、房主管理和清理任务。

### 4.2 不变量

- `OPENID` 只在云函数请求期间使用，不写入应用集合、不返回客户端。
- 成员权限由服务端微信身份和 membership 决定；客户端传入的 OpenID、role、owner、memberId 或 participantId 不能提升权限。
- member 决定权限，participant 只参与计算；每个有效 member 唯一对应一个 participant。
- 昵称和 Emoji 都是不可信展示输入，必须在服务端规范化和校验，不能用于鉴权。
- 普通成员更新资料时只能修改自己的 nickname/Emoji；房主身份不能借 profile 请求修改他人。
- 旧的 `claimParticipantId`、`newParticipantName` 和头像文件字段继续被拒绝。
- 日志、响应和客户端缓存不得泄露原始 OpenID、AppSecret、上传私钥或邀请 token 原文。

### 4.3 主要失败场景

- 恶意客户端伪造 member/participant/role，试图编辑他人资料或执行房主操作。
- 利用邀请预览枚举房间成员、Emoji、昵称或账单事实。
- 弱网重试创建重复 member/participant，或并发加入分配重复默认 Emoji。
- 旧客户端缺少 Emoji 字段导致房间无法读取，或新客户端把非法字符串写入历史/分享图。
- 被移除成员继续使用旧 revision 写入；服务端必须先鉴权再处理冲突。

## 5. 技术工作包

### WP0 — 基线与兼容性

- 保留现有两账号服务测试作为行为基线。
- 明确本地持久化、共享 snapshot、历史快照和分享画布中的头像字段流向。
- 不把当前未提交的 helper 草稿当成完成状态。

### WP1 — 单一 Emoji 领域模块

- 建立唯一的白名单、校验、稳定候选算法、避重分配和展示模型。
- 本地 UI、共享 UI、历史和结算图只消费这一模块，不各自复制哈希或颜色逻辑。
- 补齐稳定性、避重、显式覆盖、非法输入和旧数据兼容测试。

### WP2 — 首页双模式

- 用紧凑模式选择替换共享 banner 和创建弹层。
- 本地流程和共享内联表单按选中模式显示并保留各自草稿。
- 补齐 CloudBase 不可用和邀请直达场景。

### WP3 — 本地与历史体验

- 新参与人立即获得并保存 Emoji；参与人 chip、支出分摊、结算列表、历史卡和分享图统一显示。
- 增加轻量选择面板，不新增独立设置菜单。
- 旧本地记录与历史记录无 Emoji 时仍能读取并获得稳定回退。

### WP4 — 共享资料契约

- 扩展 `room_create`、`room_join`、`room_profile_update` 与 snapshot 的受限 Emoji 字段。
- 服务端事务负责共享成员的默认避重分配和 member/participant 同步。
- 增加只能修改自己、邀请预览不泄露、非法字段拒绝、重复加入幂等等负向测试。

### WP5 — 移动视觉与完整验证

- 在微信开发者工具检查 320、390、430px 的首页两模式、加入页、房间页、Emoji 选择器、历史和结算分享图。
- 检查浅色/深色（若小程序保留主题）、长中文昵称、不同币种、键盘弹出和至少 10 人账单。
- 运行仓库测试、类型检查、Web 构建和云函数语法检查；不得通过删除安全断言来通过测试。

### WP6 — 文档、提交与受控上线

- 更新小程序说明、运行手册、隐私文案和发布验收清单。
- 本地验证后提交并正常推送；不提交凭据。
- 生产云函数部署、隐私指引修改、小程序上传、体验版/审核/发布都分别等待用户确认。
- 获权后使用两个真实微信账号完成群邀请、加入、共同编辑、Emoji 同步、移除撤权和分享图验收。

## 6. 验收标准

- 首页首次打开能一眼区分本地快速分账与共享账单，不需要先进入二级菜单。
- 本地模式默认可用，切换共享模式不会丢失本地输入；共享创建不要求本地参与人或支出。
- 新参与人/成员默认得到不重复、持久稳定的 Emoji，完整昵称仍清楚显示。
- 用户可在当前工作流内更换 Emoji；共享成员不能修改他人资料。
- Emoji 在参与人列表、支出、结算、历史和导出图片中一致且可读。
- 旧数据、无 CloudBase、本地离线、币种、支出编辑和结算算法无回归。
- 非成员、过期邀请持有者和被移除成员无法读取完整房间或成员资料。
- 未经再次确认，不改变生产资源、微信隐私指引或线上版本。
