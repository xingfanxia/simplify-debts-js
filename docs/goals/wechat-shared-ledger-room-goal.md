# Goal: 为微信小程序实现安全可用的多人共享分账房间

## Intent

让用户把当前本地账单主动转换为共享账单，通过微信邀请朋友加入同一个房间。成员加入后可以查看并共同编辑参与人和支出，所有人的结算结果保持一致。

小程序仍以简洁、易用、中文工具为定位。普通账单默认只保存在本机；只有用户明确点击“创建共享账单”后才上传数据。安全、隐私、数据正确性优先于实时动画或社交功能。

## Done state

### 本地与共享模式

- 现有本地账单继续完全离线可用。
- 未经用户明确点击“创建共享账单”，任何参与人、支出或结算数据都不得上传。
- 当前账单主操作区提供清晰的“创建共享账单”入口。
- 创建前明确说明该账单将同步给房间成员。
- 创建完成后显示房间状态、同步状态、成员入口和邀请入口。
- 本地账单、历史记录、编辑支出、多币种、结算图分享等现有功能无回归。

### 房间流程

- 实现房间创建、邀请、邀请预览、加入、读取、编辑、成员管理和退出。
- 分享路径使用 `/pages/room/room?invite=<token>`。
- 接收者打开邀请时，只能看到房间名称、币种及可认领的参与人，不得在加入前看到支出或余额。
- 加入者可以输入自己在房间中的显示名称、认领已有参与人，或新增自己作为参与人。
- 加入后才能读取完整账单。
- 所有有效成员可以新增、编辑和删除支出。
- 房主可以撤销邀请、移除成员、归档或删除房间。
- 被移除成员在下一次请求或 3 秒内失去访问权限。

### 数据与服务端

按照 `docs/wechat-shared-room-plan.md` 实现并验证：

- `ledger_rooms`
- `ledger_members`
- `ledger_participants`
- `ledger_expenses`
- `ledger_invites`
- `ledger_mutations`

实现等价能力：

- `room_create`
- `room_invite`
- `room_join_preview`
- `room_join`
- `room_get`
- `room_mutate`
- `room_manage`

要求：

- 原始集合仅管理端读写；小程序客户端不得直接读写原始集合。
- 每个云函数使用 `cloud.getWXContext().OPENID` 确定调用者身份。
- 不信任客户端传入的 OpenID、memberId、role、owner 或权限标记。
- OpenID 只保存在服务端，不返回客户端。
- 金额使用最小货币单位整数。
- 写入携带 `baseRevision` 和随机 `mutationId`。
- 使用服务端事务维护版本、邀请使用次数和多文档一致性。
- 重复提交同一 `mutationId` 不得生成重复支出。
- 版本冲突必须返回明确的 `revision_conflict` 和最新快照，不能静默覆盖。
- 邀请 token 至少 128 bit、可过期、可撤销、可限制次数；数据库只保存 hash。
- 房间 ID、成员 ID 和支出 ID 都不能作为授权凭证。

### 界面要求

- 小程序只提供中文界面和不同币种切换。
- 延续当前简洁、现代、克制的工具型设计。
- 易用性和可读性优先。
- 不增加荧光绿、大面积品牌标语、营销文案或不必要的菜单层级。
- 房间创建、邀请、加入、同步冲突和离线状态必须有清晰反馈。
- 所有主要操作在常见微信手机视口下可直接理解和点击。

### 隐私与安全

- 普通本地账单保持“仅本机保存”。
- 共享账单清楚标注为云端同步。
- 客户端响应、日志和错误信息不得包含 OpenID、AppSecret 或私钥。`room_invite` 为生成微信分享路径而短暂返回邀请 token 是唯一例外；token 不得进入日志、错误信息或本地持久化。
- 任何此前在聊天中出现过的 AppSecret 都视为已暴露；不得写入代码、配置或日志，真正需要使用前要求用户轮换。
- 凭据首先从 `~/creds/wechat/` 查找，只通过环境或工具要求的安全路径使用，绝不提交进仓库。
- 补充云端数据保留、退出、移除和删除行为说明。
- 在共享功能正式开放前更新小程序隐私保护指引和审核说明。

## Proof

### 自动化检查

运行：

- `npm test`
- `npm run typecheck`
- `npm run build`

为房间服务端增加可重复运行的测试命令，并覆盖：

- 非成员通过 roomId 读取被拒绝；
- 篡改客户端 OpenID、角色或 owner 标记无效；
- 未加入用户只能获得最小邀请预览；
- 过期或撤销邀请无法加入；
- 被移除成员无法继续读写；
- 重放同一 mutation 不产生重复数据；
- 两个成员基于相同 revision 并发修改时，其中一个得到明确冲突；
- 金额、币种、字符串长度和数组大小等非法输入被拒绝；
- 云函数响应不泄露 OpenID 或密钥；除 `room_invite` 的一次性分享路径外不返回 token，且任何 token 都不得进入日志或本地持久化。

所有命令必须退出码为 0，且不得通过删除、跳过或弱化测试来获得通过。

### 本地检查

- 微信开发者工具能够正常编译、启动和操作小程序。
- 本地账单在没有网络和没有 CloudBase 配置时仍能使用。
- 共享入口受功能开关控制；云环境未准备好时不得显示虚假成功状态。
- 分享路径能正确解析 invite 参数并进入邀请页。

### 真机检查

获得明确的云部署和小程序上传授权后，使用两个不同微信账号验证：

1. A 创建共享账单并邀请 B；
2. B 打开分享，只看到安全预览；
3. B 认领或新增参与人后加入；
4. A/B 分别新增和编辑支出，另一端在 3 秒内刷新；
5. 重复点击提交不产生重复记录；
6. 并发编辑不会静默覆盖；
7. A 移除 B 后，B 无法继续读取或写入；
8. 过期、撤销和重复使用邀请符合限制；
9. 本地账单从未因共享功能而自动上传。

## Non-goals and invalid shortcuts

第一版不实现：

- 聊天；
- 微信头像或昵称授权；
- 订阅消息；
- 朋友圈增长功能；
- 复杂管理员层级；
- 离线编辑队列；
- 未经证明安全的数据库实时监听；
- Web、iOS、Android 跨端账号同步。

禁止以下捷径：

- 不得把 roomId 或短房间码当作读取权限；
- 不得由客户端直接访问原始账单、成员或邀请集合；
- 不得把 AppSecret、OpenID 或代码上传私钥写入客户端或仓库；
- 不得只在前端隐藏按钮而省略服务端权限检查；
- 不得保存可与支出事实漂移的结算结果；
- 不得为了“实时”而开放包含 OpenID 或邀请信息的集合；
- 不得在未部署、未真机验证时声称线上共享功能已经完成。

## Priorities and tradeoffs

1. 权限、隐私和账单数据正确性；
2. 本地模式不回归；
3. 简洁易懂的邀请与加入体验；
4. 并发和重试可靠性；
5. 同步速度；
6. 动画和视觉装饰。

发生冲突时，保留更高优先级并报告具体影响。宁可显示刷新或冲突提示，也不能静默覆盖数据。
